## 时间切分和冷启动怎么处理

- 模型和原训练快照冻结不变。T0=2020-08-19T09:37:39.597000+00:00，晚于或等于所有原训练事件；验证使用 (T0,T1]。
- T1=2020-08-26T05:03:14.602000+00:00，晚于或等于原 checkpoint 选择所用验证事件；测试严格在 T1 之后。所有用户使用同一时间边界。
- 仍按首次曝光 watch_ratio>=1 定义正例；同一用户物品不跨窗口。时间缺失的用户物品对不作为候选或标签。
- 原双塔曾用旧验证集选择 epoch，所以新验证窗口与其选模型数据有重叠；所有组共用同一 checkpoint。新测试时间晚于该选择窗口，没有把旧模型训练事件或选模型验证事件重新算成新测试。
- 物品目录仅包含窗口开始前已出现的物品。全局首次有效曝光作为可用时间的保守代理，尚无真实发布时间，不能把这个代理等同于精确上架时间。
- 所有用户在截止时间前的全部曝光（含负例）均过滤。训练有正交互为暖物品；训练无正交互为冷物品。
- 双塔的随机冷向量完全退出候选评分。暖物品三路复用原训练权重与统计；冷物品统一按窗口开始前的不同用户曝光数排序，同分按 item ID。
- 三组用同一冷队列、同一插入位置规则：输出第 r 位前累计预留 floor(r×冷池数/总池数) 个冷位置，空队列由另一侧补齐。比例来自固定候选池，不使用验证/测试点击率。
- Agent 只能修改暖物品融合与排序的 Python 代码；本轮不修改冷队列或比例。这是为了比较算法研究带来的排序收益，不能据此宣称 Agent 自己学会了冷启动。

## 相同预算和 Memory 的实际含义

两组预算上限完全相同：3 次算法实验、3 次 LLM 请求、240秒、8次工具、2次历史读取。固定策略不搜索，复用同一个公共基线。公共基线反馈只计算一次，不重复扣作新算法实验。

无记忆组：3次连续代码实验，组内仍保留上一轮结果作为研究反馈；“无记忆”指没有跨任务历史，不是每轮清空对话。
有记忆组：先用1次代码实验生成同协议的真实历史，再新开研究任务读取该历史，继续2次代码实验。历史生成成本计入这组，未额外赠送指标或实验。两组没有读取此前不兼容的旧切分历史。

## 实际研究轨迹

### 无记忆 Agent

**累计实验 1：keep，验证 NDCG@20=0.331772**

假设：基线 round-robin 让 two_tower 的低 train_count 噪声项与强热门项交替，稀释了前 20 位的强正例密度。改用 RRF 融合三通道（two_tower 降权），并对被 itemcf+popularity 双通道同时支持的项加一致性加成，应提升暖段 NDCG@20。

反馈分析：首轮无历史实验，基于基线真实反馈：整体 NDCG@20=0.2514，暖段 0.2470、冷段 0.0244（冷段固定不可改）。候选示例显示 itemcf 与 popularity 排名高度一致且对应高 train_count 强项，two_tower top 项多为 train_count=1~6 的噪声。因此判断 round-robin 交替会稀释强项密度，尝试 RRF+一致性加成。

代码：`E:\PythonProject\recsys-agent\experiments\2026-11-13-kuairec-fair-study\no_memory\online\research-recommendation-66865871a0\trial_01\algorithm.py`。

**累计实验 2：discard，验证 NDCG@20=0.327706**

假设：Recall@100 已近上限，继续提升 NDCG@20 需精排头部。降低 two_tower 权重至 0.25、提高 itemcf+popularity 一致性加成至 0.30、加入 train_count 对数可靠性先验、RRF k 从 60 降到 40，应进一步把高可靠强正例提到前 20。

反馈分析：第1轮真实反馈：NDCG@20 0.2514→0.3318（+0.0804），暖段 0.2470→0.3330，Recall@20 0.156→0.202，但 Recall@100 几乎不变（0.708→0.709）。这证明 RRF+一致性假设成立，且提升来自"把强正例从后往前排"而非扩大覆盖。因此第2轮聚焦前20精排：进一步降 two_tower 权重（其 top 项多为低 train_count 噪声）、提高一致性加成、引入 train_count 对数先验，并缩小 RRF k 让头部名次差异更显著。

代码：`E:\PythonProject\recsys-agent\experiments\2026-11-13-kuairec-fair-study\no_memory\online\research-recommendation-66865871a0\trial_02\algorithm.py`。

**累计实验 3：keep，验证 NDCG@20=0.332380**

假设：第2轮失败源于过度压制 two_tower 与过度热门化。回到第1轮配置并温和提高 two_tower 权重至 0.6（恢复互补信号）、一致性系数降至 0.12、去掉 train_count 先验，应能超过第1轮的 0.3318。

反馈分析：第2轮真实反馈：NDCG@20 0.3318→0.3277（-0.0041），暖段 0.3330→0.3286，Recall@20 0.202→0.1998，全面小幅下降，被 discard。这否定了"进一步压制 two_tower + 加 train_count 热门先验 + 缩小 k"的方向：说明 two_tower 权重 0.5 已接近最优，过度压制损失互补信号，train_count 先验把排序推向纯热门反而伤害个性化。第3轮据此反向修正：回到第1轮配置，温和提高 two_tower 权重至 0.6 恢复互补信号，一致性系数略降至 0.12，彻底去掉 train_count 先验，k 保持 60。

### 有记忆 Agent

**累计实验 1：keep，验证 NDCG@20=0.333843**

假设：基线直接按 round-robin 候选顺序输出，导致 two_tower 前排的低热度长尾物品（train_count 1-9）与热门物品交替占据前 20，浪费了高一致性热门物品的排序位置。假设：用多通道 RRF 一致性 + 通道覆盖奖励 + 热度对数先验重排暖候选，能把多通道共同支持的高质量物品上移、把单通道低热度长尾下沉，从而提升暖物品 NDCG@20，同时因输出全部候选不损害 Recall@100。

反馈分析：首轮无历史实验，分析共享基线：NDCG@20=0.2514（暖 0.2470，冷 0.0244），Recall@20=0.1562，Recall@100=0.7082。基线 rank 直接返回候选原始顺序（round-robin 融合顺序）。从候选样例看，two_tower 前排大量 train_count 极低（1-9）的长尾物品，而 itemcf/popularity 前排是 train_count 数百的热门物品；round-robin 交错使长尾占据前 20 位置。判断：多通道一致性与热度先验应能改善暖排序。

**累计实验 2：keep，验证 NDCG@20=0.334052**

假设：在上一轮 RRF+覆盖+热度先验（NDCG@20=0.3338）基础上，强化热度对数先验权重并引入通道一致性门控：仅当物品被≥2通道共同支持时给予完整热度加成，单通道长尾物品热度加成减半。预期更激进地下沉单通道低热度长尾（two_tower 前排 train_count 1-9 的物品），同时保留多通道热门物品，继续提升暖 NDCG@20，且因输出全部候选不损害 Recall@100。

反馈分析：上一轮真实反馈：RRF+覆盖+热度先验把 NDCG@20 从基线 0.2514 提升到 0.3338（+0.0824），暖 NDCG@20 0.2470→0.3350，Recall@20 0.1562→0.2023，证实多通道一致性+热度先验有效。但 Recall@100 略降（0.7082→0.7076），说明排序把部分长尾正样本挤出前100。候选样例显示 two_tower 前排大量 train_count 1-9 的长尾物品，上一轮热度权重 0.0015 偏小，压制不足。因此本轮强化热度先验并加通道一致性门控：多通道支持才给完整热度加成，单通道长尾减半，更激进下沉单通道低热度长尾。

**累计实验 3：discard，验证 NDCG@20=0.333668**

假设：热度先验调参已饱和（两轮 NDCG@20 几乎持平）。本轮假设：在已验证的 RRF+覆盖+热度骨架上，叠加通道内分数 min-max 归一化信号（小权重），能捕获纯 rank 丢失的"通道内相对强弱"信息，让通道内明显领先的物品获得额外提升，从而在暖 NDCG@20 上取得超过 0.33405 的增益，同时因输出全部候选不损害 Recall@100。

反馈分析：上一轮真实反馈：强化热度先验+单通道减半门控后 NDCG@20=0.33405，仅比前一轮 0.33384 微增 +0.0002，几乎持平；Recall@20 略升(0.20234→0.20291)但 Recall@100 略降(0.70765→0.70752)。这说明热度先验调参已收益递减、饱和——RRF 结构已捕获主要信号，继续调热度权重无空间。真正未利用的信号是通道内分数尺度：候选样例显示 itemcf 分数(~2-24)、two_tower(~-0.17~0.38)、popularity(=train_count)尺度差异巨大，而前两轮只用 rank 做 RRF，丢弃了通道内分数相对强弱。因此本轮保留已验证的 RRF+覆盖+热度骨架，叠加通道内 min-max 归一化分数项(小权重 0.0015)作为微调，捕获"通道内明显领先"信号，风险可控。

## 证据和边界

- protocol.json：开跑前固定的时间、标签、冷启动规则和预算。

- run.py：整个实验；verify_and_report.py：只读取保存结果核对并生成报告。
- baseline_cache 小型定点检查确认公共基线不消耗新增代码实验额度；输入为明确的测试替身，不混入真实指标。

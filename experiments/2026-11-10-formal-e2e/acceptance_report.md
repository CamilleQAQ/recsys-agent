# 搜广推与多智能体端到端验收

**结论**　推荐、搜索、广告三个业务链路均完成了本次批量离线评估。真实 Research Agent 在项目原有的小样本调度入口里完成了四次新实验，读取首轮反馈后改变了下一轮配置，并且新记录能被另一个进程复用。当前具备**预算约束下的小样本端到端自主研究能力**。三条批量评估走现有业务 API，统一入口直接调度同等规模尚未验证。

从启动到完成主要核对约 6 分钟，新增工件约 442 MiB，低于 2 小时和 3 GB。正式业务评估和总控任务均复用现有权重。另执行一次隔离 BPR-MF 训练用于验收权重生命周期。验收脚本和工件均放在本目录。

## 三条业务链路

### 推荐

在 KuaiSAR-small 完整测试集上一次评估 **2,000 个用户、454,717 个候选目录物品、4,275 个留出点击目标**。双塔和 MIND 各取前 100，轮流融合到前 100，LightGBM 精排和类目多样性重排最终为每个用户返回 20 条。逐用户检查候选衔接、唯一性和数量通过。

| 阶段 | 实际命中的目标数 |
| --- | ---: |
| 两路召回前 100 并集 | 126 |
| 融合候选池前 100 | 69 |
| 融合顺序前 20 | 25 |
| LightGBM 精排前 20 | 11 |
| 最终前 20 | 12 |

融合 Recall@100 为 **0.015325**，最终 Recall@20 为 **0.002175**，NDCG@20 为 **0.001021**，HitRate@20 为 **0.006000**。批量运行含输出和对账耗时 **41.68 秒**。召回没有取回 4,149 个目标，现有排序也未保住所有融合前列的目标。 运行指标（本地文件：`recommendation/result.json`） · 最终结果（本地文件：`recommendation/final.json`） · [命中对账](audit.json)

### 搜索

从日志按固定种子抽取 **1,000 个会话**并补齐原始曝光，使用 **14,575 个带 caption 的物品**构建同一套 BM25 和 FAISS 索引，重新加载后查询。934 个会话有点击，1,988 个点击目标中 1,621 个进入索引，覆盖 **81.5%**。未入库目标计为未命中。24 个会话没有返回结果。向量是无需训练的 token 哈希。

| 方法 | Recall@20 | NDCG@10 | 查询耗时 P95 |
| --- | ---: | ---: | ---: |
| BM25 | 0.37612 | 0.20473 | 1.12 ms |
| FAISS 向量 | 0.31675 | 0.15914 | 16.18 ms |
| RRF 混合 | 0.35246 | 0.18977 | 17.45 ms |
| 混合加精排 | 0.36568 | 0.20615 | 18.50 ms |

混合加精排的 NDCG@10 略高于 BM25，Recall@20 仍较低。耗时按实测阶段汇总，排除索引构建，整项运行 **46.63 秒**。点击是曝光日志中的离线相关性标签。 评估结果（本地文件：`search/result.json`） · 逐查询记录（本地文件：`search/query_results.jsonl.gz`）

### 广告

DIN 对已有 **5,577 条曝光、5,276 个请求**做点击概率推理、请求内排序和按时间回放，其中 282 个请求有多个广告候选。测试切分仅有 43 条曝光、36 次点击。AUC **0.58333**，LogLoss **0.83217**，来自固定初始化的接口权重，仅记录本次输出。

| 二价竞价回放 | 成交请求 | 成交率 | 模拟花费 | 前十广告主花费占比 |
| --- | ---: | ---: | ---: | ---: |
| 总预算 500 | 2,126 | 40.30% | 499.74 | 16.35% |
| 总预算 500、每广告主上限 8 | 2,133 | 40.43% | 500.00 | 14.83% |

真实数据是历史曝光和点击。出价、预算和扣费均为模拟，缺少真实转化标签。检查了时间顺序、广告位数量、扣费总额和广告主上限，整项耗时 **6.30 秒**。 运行与回放结果（本地文件：`ads/result.json`） · 逐请求回放（本地文件：`ads/request_replay.jsonl.gz`）

## 真实多智能体研究

总控是 DeepSeek 真实工具调用。总控调用的三个子智能体使用项目当前的本地执行计划，业务工具和数据均为真实。任务在 **33.13 秒**内结束，消耗 **8 次 LLM 请求、18 次工具调用、4/4 次新实验、1 次历史查询和 1 次工件读取**。

| 轮次 | 决策和实际返回 |
| --- | --- |
| 1 | 查询 30/70 历史。命中 128 用户融合实验，历史 Recall@100 为 0.013672，作为先验。 |
| 2 | 查询 RAG，返回 3 条带出处的记录。 |
| 3 | 选双塔和 MIND，深度 100。在 64 个验证用户、175 个目标上，召回并集命中 3，最终前 20 命中 0。 |
| 4 | 从共享实验库读回首轮工件和结果。 |
| 5 | 加入 Popularity，候选深度改成 200。召回并集命中 14，融合前 20 命中 1，精排和最终前 20 都是 0。两项参数同时变化，无法拆分贡献。 |
| 6 | 调用 Search Agent 执行混合检索和精排，实际返回 5 条。 |
| 7 | 调用 Ads Agent。DIN 在 51 条验证曝光上完成 CTR 推理，另完成 5 个请求的排序和模拟竞价。 |
| 8 | 停止并总结。模型提出下一步对比融合直接出榜与精排后的差异，该建议未继续执行。 |

四项新业务记录均入库。另一个进程按任务 ID、模型和切分复用了第二轮推荐记录，启动 **0 次**新实验。独立的零预算任务尝试启动新实验，被拦截并返回失败，启动 **0 次**。 原生调用（本地文件：`research/native_llm.jsonl`） · 完整决策（本地文件：`research/tasks/task-20261110T144123-6430f6/decisions.json`） · 结果（本地文件：`research/result.json`） · 跨进程复用（本地文件：`research/memory-check.json`） · 零预算拦截（本地文件：`research/budget-check.json`）

训练接口另做一次 BPR-MF 的真实训练，上限 1 轮、4 批，训练损失 0.693148。新 checkpoint 写入验收目录，后续评估确认加载的是该文件及对应 SHA-256，默认权重校验值未变。总控这轮没有自主发起训练。 训练和恢复结果（本地文件：`training-check/result.json`）

## 固定规则、Optuna 与记忆对照

使用项目已有的配额回放框架，在同一份 128 个验证用户、362 个点击目标和已冻结的真实指标上执行。各方最多揭晓 2 个新配置。只给有记忆组额外展示已有的 70/30 历史，两个 Agent 均是真实 LLM。

| 策略 | 最佳配额 | 命中 | Recall@100 | 新揭晓 | LLM 请求 |
| --- | --- | ---: | ---: | ---: | ---: |
| 固定规则 | 30/70 | 5 | 0.013672 | 2 | 0 |
| 无记忆 Agent | 30/70 | 5 | 0.013672 | 2 | 3 |
| 有记忆 Agent | 30/70 | 5 | 0.013672 | 1 | 2 |
| Optuna | 未运行 | — | — | — | — |

本地反馈规则同样选中 30/70，揭晓 2 次。有记忆 Agent 本次少揭晓一个配置，最佳效果持平。无记忆和有记忆两组的单次 LLM 回放耗时分别为 3.54 秒和 4.28 秒。该比较复用真实评估工件，每种 LLM 条件一次，结论限于本次回放。仓库无 Optuna 接入，当前 Python 环境也未安装，按验收范围保留缺项。 对照轨迹与源工件指纹（本地文件：`strategy-comparison/run-20261110T064149Z-30412/report.md`）

## 发现的问题与未验证项

1. **总控搜索参数会被任务文本覆盖。** LLM 请求 hybrid，任务原文含“精排”，执行实际变成 rerank。此次业务目标恰好需要精排，结果完整，但不能把这个模式变化算作 Agent 自主选择。 [参数合并实现](../../src/recsys/platform/research_agent.py#L903) · 运行记录（本地文件：`research/result.json`）
2. **推荐诊断的 survived 容易被误读。** 输出为 4，表示始终保留在各阶段前 20 的目标。另有 7 个被精排拉回，1 个在最终重排时进入前 20，所以最终真实命中是 12。正式报告已用最终列表对账。 [诊断实现](../../src/recsys/pipeline/chain.py#L298) · [实际对账](audit.json)
3. **广告预算原因会误标。** 总余额仍为正但低于 0.30 保留价时，后续无法投放。两组分别有 3,150 和 3,099 个尾部请求被标为广告主预算不足。成交数和花费对账通过，耗尽原因统计受到影响。 [竞价实现](../../src/recsys/ads/auction.py#L153) · [实际对账](audit.json)
4. **总控结论存在归因过度。** 第二轮同时改模型和候选深度，且仍有 161/175 个目标不在召回并集。数据只能说明这一组调整把一个目标带进融合前 20、随后精排未保留，无法断言主要瓶颈只在精排。 [逐轮对账](audit.json)
5. **验收边界。** 总控工具当前面向小样本，批量三路由验收脚本调用原业务入口。未验证总控直接发起大批量任务、自动训练和发布权重、把总结自动写成新 RAG 规则、真实 CTR/CVR 效果、在线投放或在线收益。推荐 MIND 的随机初始化依赖用户分批，跨运行的策略对照应固定顺序和分批。 [MIND 推理实现](../../src/recsys/models/mind.py#L116) · [总控工具定义](../../src/recsys/platform/research_agent.py#L257)

本次新增的运行脚本保留了实际数据口径和入口。它们生成独立目录，重复执行前应指定新输出目录。

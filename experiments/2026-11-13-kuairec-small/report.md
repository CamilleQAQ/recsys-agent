# KuaiRec small_matrix 首轮推荐实验

使用官方 KuaiRec 2.0 small_matrix，1,411 用户、3,327 个视频。原始 4,676,570 行。通过官方 ZIP 中单个成员的范围下载取得数据，CRC32 校验通过。

排除 181,992 个缺少时间戳的用户—视频对。第一次播放的 watch_ratio >= 1.0 为正例。同一用户按首次曝光的不同时间戳分成 80% / 10% / 10%，同时间戳归同侧。固定阈值和协议之后才运行模型，未按测试指标调参。

训练正例 1,177,823，验证 140,775，测试 153,264。测试有正例的用户 1,410。过滤测试开始前所有已曝光物品，每用户可选物品数最小/中位/最大为 [356.0, 463.0, 597.0]。全目录计算，再过滤已曝光物品。

| 方法 | Recall@20 | Recall@100 | NDCG@20 |
| --- | ---: | ---: | ---: |
| popularity | 0.027469 | 0.125967 | 0.125825 |
| itemcf | 0.023865 | 0.120884 | 0.110090 |
| two_tower | 0.061280 | 0.270159 | 0.330743 |

双塔为项目 TwoTowerModel 的 32 维 ID 表示，Adam lr=0.01，批大小 1024，固定 5 轮。批内已知训练正例被屏蔽为假负例。按验证 NDCG@20 选第 1 轮，随后仅在测试集评价一次。Popularity 按训练次数，ItemCF 按训练物品余弦共现。

原始数据观测密集不代表时间外推无冷启动。测试 120,308/153,264 个正例涉及训练期零正反馈物品。选择整段时间留出形成了较强的物品分布变化，不能将本次结果与 KuaiSAR 不同协议的 Recall 直接视作算法改进。

本次协议是显式配置的首轮时间对照，区别于项目已有的 KuaiRec big_matrix 默认最后两条正反馈留出。首次尝试在数据检查阶段发现缺失时间，第二次在检查阶段发现验证和测试正例用户集合相差一人；两次均在训练前停止，之后采用全用户打分、各自正例用户计分。

数据处理、三基线及双塔训练耗时 65.56 秒，下载另计。只保存一个验证集选中的新权重。

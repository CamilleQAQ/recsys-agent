# KuaiRec 验证与测试反转：原因排查

结论：已定位到明显的冷热物品分布变化，以及等权 RRF 对暖物品的偏向。未发现本次融合公式错误、加载错推荐文件或按用户切分顺序颠倒。另发现一个重要实验限制：双塔冷物品向量完全没有训练过，上一轮双塔测试指标较高不能归因于它学会了冷启动推荐。

本次只做冻结权重推理、已有推荐结果拆解和代码对照，没有训练、调参或重新运行 Agent。生产源码和原实验结果未修改。

## 1. 数据切分：顺序正确，分布严重变化

| 统计 | 验证集 | 测试集 |
|---|---:|---:|
| 有正例的用户 | 1,411 | 1,410 |
| 正例数 | 140,775 | 153,264 |
| 训练无正交互的正例数 | 22,875 | 120,308 |
| 训练无正交互的正例比例 | 16.25% | 78.50% |
| 训练连曝光都没有的物品贡献的正例比例 | 14.67% | 77.53% |
| 每用户可推荐物品数中位数 | 781 | 463 |
| 每用户可推荐暖物品数中位数 | 464 | 209 |
| 每用户可推荐冷物品数中位数 | 317 | 253 |

这里的冷物品按全体训练正交互计数为零定义；暖物品指至少有一条训练正交互。全目录 3,327 个物品中，328 个没有训练正交互，其中 283 个连训练曝光都没有。测试冷正例 120,308 个中，有 118,833 个来自训练无曝光的物品，不能简单归因为“用户交互抽样太少”。

原切分按每个用户的首次曝光时间取前 80%、中间 10%、最后 10%，边界相同时间不拆。检查结果：每个用户的训练正例时间严格早于其验证正例，验证正例严格早于测试正例；上一轮 finish.py 也已核对原始 CSV 重建的三份切分与保存文件完全一致。因此没有发现验证/测试拿反或用户内部时间穿越。

但这不是严格的全局时间切分，各用户的切分日期不同。实际全局正例日期范围（UTC）为：

- 训练：2020-07-03 至 2020-08-19。
- 验证：2020-08-10 至 2020-08-26。
- 测试：2020-08-18 至 2020-09-05。

日期有重叠，可能存在其他用户的训练事件晚于某次评估请求的情况。当前实验不能解释成严格的全站时间回放。不过这与本次“验证多暖物品、测试多冷物品”的直接计数证据是两件事。

目前的候选过滤只剔除该用户已经曝光的物品，没有按真实发布时间建立当时可用物品目录。只有首次观察时间，未取得真实发布时间，因此不能据此断言具体哪些推荐在当时尚未发布；这也是尚未排除的协议限制。

## 2. 融合机制：RRF 的暖物品收益在测试中被冷物品损失抵消

这次 RRF 为每路候选累加 1/(60+通道内名次)。一件物品同时被多路召回，会获得明显加分。这是实际代码的正确行为，不是实现时意外重复累加。

三路的冷物品能力不对称：

- ItemCF 对训练无正交互的物品得分为零，本次过滤零分，因此无法推荐冷物品。
- Popularity 优先训练有点击的物品；验证 top100 无冷物品，测试只有少量零分补位。
- 双塔推荐了大量冷物品，但其向量未被训练，见下一节。

验证候选并集中，暖物品有 132,842 个用户物品候选被至少两路支持，冷物品为 0；测试对应为 138,047 和 55。因此 RRF 主要把暖物品提到前面。两个切分的 RRF top20 都完全没有冷物品。

| top20 原始命中数 | 验证固定轮询 | 验证 RRF | 测试固定轮询 | 测试 RRF |
|---|---:|---:|---:|---:|
| 暖物品命中 | 4,050 | 7,773 | 1,628 | 3,781 |
| 冷物品命中 | 517 | 0 | 4,547 | 0 |
| 总命中 | 4,567 | 7,773 | 6,175 | 3,781 |

验证集：RRF 多命中 3,723 个暖物品，少命中 517 个冷物品，所以总体改善。

测试集：RRF 多命中 2,153 个暖物品，少命中 4,547 个冷物品，所以总体下降。其暖物品能力并没有突然失灵，主要是评估目标换成以冷物品为主。

按原始每用户正例数分母拆解 Recall@20，两个分项可直接相加：

| 切分/策略 | 暖物品贡献 | 冷物品贡献 | 总 Recall@20 |
|---|---:|---:|---:|
| 验证固定轮询 | 3.2987% | 0.3657% | 3.6644% |
| 验证 RRF | 6.2908% | 0 | 6.2908% |
| 测试固定轮询 | 1.1379% | 3.0639% | 4.2018% |
| 测试 RRF | 2.6610% | 0 | 2.6610% |

同样使用原始 IDCG 分母拆解测试 NDCG@20：固定轮询的暖物品贡献 0.050740、冷物品贡献 0.173470，总计 0.224210；RRF 暖物品贡献 0.123233、冷物品贡献 0，总计 0.123233。NDCG 的反转也由这一机制直接解释。

若仅保留暖正例作为相关标签（推荐列表保持不变），测试 Recall@20 为固定轮询 6.16%、RRF 14.23%，评估用户同为 1,409。这个条件指标只作诊断，不能替换完整测试集的正式成绩。

## 3. 双塔：测试优势大部分来自未训练的冷物品向量

用训练时相同的 seed=42 重新生成初始化模型，与现有 checkpoint 比较：328 个冷物品 embedding 全部逐元素完全相同；2,999 个暖物品 embedding 全部发生了变化。此操作仅初始化和比对，没有训练。

这说明冷物品向量确实没有得到学习，既不是加载到了另一份冷启动模型，也不是使用了内容特征。当前双塔是 ID-only 模型。

双塔测试 top20 中 91.10% 的推荐位置为冷物品。共命中 9,233 个正例，其中 8,946 个（96.89%）为冷物品。其整体 Recall@20=6.1280% 中，冷物品贡献 5.9287 个百分点，暖物品仅贡献 0.1993 个百分点。

因此必须修正上一轮结果的解读：双塔的测试指标数值可以复算，但大部分命中来自未经训练的冷物品排序，不能作为模型已经学到了良好个性化或冷启动能力的证据。未训练向量为何大量排在暖物品前，尚未进一步拆解其分数校准；本报告不将其归结为某一具体优化器或训练轮数问题。

## 4. 融合实现与加载核对

- 使用冻结权重重新生成三路测试 top100，逐个用户与上轮保存的三份 json.gz 完全一致。
- 验证和测试的固定轮询结果均与独立的“按名次依次交错、去重”实现逐项一致。
- 验证和测试的 RRF 结果均与独立的排名倒数求和、同规则排序实现逐项一致。
- 本次两个测试融合列表均与原实验保存的列表完全一致。
- 上轮 checks.json 已核对推荐无重复、无已曝光物品、数据映射一致，指标能从保存的推荐列表复算。

没有发现本次两种配置的融合公式、名次起点、物品 ID、通道加载或结果缓存错误。不代表已覆盖项目其他融合配置。

## 5. 为什么 Agent 没有避开

两组 Agent 都只按验证 NDCG@20 选配置，只收到整体指标，没有得到冷热分组统计。验证确实偏好 RRF，因此这个选择符合当时目标；但它没有检查验证与测试的物品人群是否变化。记忆中存的也是同一验证协议的 RRF 好成绩，不能补偿这个盲点。

此外，这是脚本预设 6 个配置中的有限选择，预算为每组 2 个新实验，不能据此声称 Agent 自动发现了普适策略。没有证据表明记忆检索或 LLM 工具调用失败导致本次效果下降。

## 6. 当前判断与未验证边界

1. **已证实的直接原因**：冷热目标比例从 16.25% 冷变成 78.50% 冷；RRF 把冷候选挤出 top20；暖物品收益不足以补偿冷命中损失。
2. **已证实的模型限制**：冷物品 embedding 未训练，上一轮单双塔较高的测试成绩不能归功于冷启动学习。
3. **没有发现的错误**：用户内时序切分反转、加载错结果、本次 RRF/轮询公式实现错误。
4. **存在的协议限制**：用户独立时间切分不等于全局时间回放；尚未核对真实发布时间与当时目录可用性。
5. **没有开展**：重训、增轮数、改融合权重、重选测试方案、重复 Agent 实验。也没有通过改测试集来制造更好的结果。

证据：diagnose.py、result.json、ndcg_decomposition.json、validation_channels.json.gz、test_channels.json.gz 均在本目录；原始实验配置和数据处理分别见上一级 run.py 与 experiments/2026-11-13-kuairec-small-scripts/run_experiment.py。
